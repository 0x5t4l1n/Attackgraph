Capabilities

Everything in one platform

A complete workflow from discovery to reporting, with all data stored locally on your machine.

🕷

Active Web Crawler

Scope-enforced async crawler with robots.txt compliance, configurable depth, rate limiting, and form discovery.

📡

Burp Suite Import

Import Burp Suite XML HTTP history exports. Credentials are redacted and endpoints normalized automatically.

📋

OpenAPI Import

Import OpenAPI 2.0, 3.0, and 3.1 specifications and cross-reference them against observed traffic.

🗺

Application Graph

Build a typed directed graph of hosts, endpoints, and relationships. Every edge is tracked with evidence source and confidence.

🔍

Security Analysis

Ten deterministic rules generate evidence-backed hypotheses with confidence scores, affected endpoints, and reproduction steps.

⚡

Attack Paths

Graph traversal discovers candidate paths from entry points to sensitive operations, prioritized by confidence.

📝

Test Plans

Structured procedures with preconditions, step-by-step instructions, expected outcomes, and evidence requirements.

📄

Security Reports

Export Markdown, JSON, or HTML reports that clearly distinguish confirmed findings from unvalidated hypotheses.

🤖

AI Assistant (optional)

Connect Ollama, OpenAI, Gemini, or OpenRouter for graph summarization. All core features work without AI.

How it works

From discovery to report

A structured workflow that keeps evidence and analysis clearly separated at every step.

01

Discover

Crawl the target or import Burp/OpenAPI traffic to collect endpoints and observations.

02

Map

Build a typed application graph with hosts, endpoints, and evidence-tracked relationships.

03

Analyze

Apply deterministic security rules to generate prioritized, evidence-backed hypotheses.

04

Validate

Review findings and execute structured test plans on authorized targets. Update status as you test.

05

Report

Export a professional security assessment in Markdown, JSON, or HTML with a clear limitations disclaimer.

Installation

Available on Arch Linux, AppImage, and .deb

No Python, Rust, or Node.js required for the pre-built packages — the backend is bundled inside.

yay -S attackgraph-bin
paru -S attackgraph-bin
git clone https://aur.archlinux.org/attackgraph-bin.git
cd attackgraph-bin && makepkg -si
attackgraph
wget https://github.com/0x5t4l1n/Attackgraph/releases/download/v1.0.0/AttackGraph_1.0.0_amd64.AppImage
chmod +x AttackGraph_1.0.0_amd64.AppImage
./AttackGraph_1.0.0_amd64.AppImage
wget https://github.com/0x5t4l1n/Attackgraph/releases/download/v1.0.0/AttackGraph_1.0.0_amd64.deb
sudo dpkg -i AttackGraph_1.0.0_amd64.deb
attackgraph
git clone https://github.com/0x5t4l1n/Attackgraph.git
cd Attackgraph
python3 -m venv .venv && source .venv/bin/activate
pip install -e "backend[dev]"
cd frontend && npm install
cargo tauri dev
⚠

Authorized testing only. Only use AttackGraph against systems you own or have explicit written permission to test. The crawler respects robots.txt by default.

FAQ

Common questions

AttackGraph is an open-source, local-first application security testing platform for Linux. It discovers web application endpoints, models them as a directed graph, applies deterministic security analysis, and generates professional security reports — without sending any data to external services.

AttackGraph is designed for penetration testers, security researchers, and bug bounty hunters who need a structured workflow from discovery to report. It assumes familiarity with web application security concepts and requires authorized access to any target.

No. AttackGraph is a passive analysis and hypothesis generation platform. It observes, models, and reasons about application structure. It does not send attack payloads, attempt authentication bypasses, or execute destructive actions. All findings are labelled as unvalidated hypotheses until you manually confirm them through your own authorized testing.

No. All project data is stored locally at ~/.local/share/attackgraph/. There is no telemetry, cloud sync, or external communication — except optional AI API calls if you configure a provider. The AI assistant can run fully locally using Ollama with no API key.

AttackGraph supports Linux x86_64. Pre-built packages are available for:

  • Arch Linux — via the AUR (attackgraph-bin)
  • Any Linux x86_64 — portable AppImage, no installation required
  • Debian / Ubuntu — .deb package

Burp Suite and OWASP ZAP are HTTP proxies that intercept and replay traffic. AttackGraph is a graph analysis and reporting layer that sits above traffic collection. AttackGraph can import your Burp Suite HTTP history to build its application graph — the two tools complement each other.

No. The AI assistant is entirely optional. Every core feature — crawling, import, graph construction, analysis, attack paths, test plans, and reports — works without any AI configuration. If you want AI assistance, Ollama runs locally with no API key required.

Open an issue on GitHub. Before contributing code, read the Contributing Guidelines — every PR must declare whether AI was used and which provider. For security vulnerabilities, follow the Security Policy for responsible disclosure.
