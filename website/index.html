Capabilities
◆

Everything you need for application security research

A complete workflow from discovery to reporting, with no data leaving your machine.

🕷

Active Web Crawler

Async crawler with scope enforcement, robots.txt compliance, rate limiting, form discovery, and configurable depth and concurrency.

📡

Burp Suite Import

Parse Burp Suite XML HTTP history. Requests are parsed, credential headers stripped, cookies redacted, and endpoints normalized.

📋

OpenAPI Import

Import OpenAPI 2.0, 3.0, and 3.1 specifications. Endpoints are extracted and cross-referenced against observed traffic.

🗺

Application Graph

Typed directed graph with host, endpoint, parameter, and auth nodes. Every edge is tracked with evidence source and confidence score.

🔍

Security Analysis

10 deterministic rules generate evidence-backed security hypotheses with confidence scores, assumptions, and reproduction steps.

⚡

Attack Paths

Graph traversal discovers candidate paths from entry points to sensitive operations, prioritized by confidence.

📝

Test Plans

Structured procedures with preconditions, instructions, expected behavior, evidence requirements, and cleanup steps.

📄

Security Reports

Export in Markdown, JSON, and HTML. Reports clearly distinguish confirmed findings from unvalidated hypotheses.

🤖

AI Assistant

Optional. Works with Ollama, OpenAI, Gemini, and OpenRouter. All core features work without AI — it is an enhancement only.

Methodology
◆

A structured path from discovery to report

Eight steps that move from evidence collection through graph analysis to validated findings.

I

Define project and scope

Configure the target URL, allowed hosts, schemes, and excluded paths. Every subsequent step respects these boundaries.

II

Collect application data

Run the active crawler, import Burp Suite HTTP history, or provide an OpenAPI specification. Combine all three.

III

Build the application graph Automated

Click Build Graph. A typed directed graph is generated from collected observations, each node carrying confidence and source.

IV

Run security analysis Automated

Ten deterministic rules analyze the graph. All findings begin as unvalidated hypotheses — never false confirmations.

V

Review findings and attack paths

Examine each finding's reasoning, affected endpoints, assumptions, and reproduction steps. Review prioritized attack paths.

VI

Execute approved test plans

Follow structured procedures on authorized targets. Update finding status as you validate or dismiss each hypothesis.

VII

Generate the security report

Export as Markdown, JSON, or HTML with executive summary, findings, attack paths, test plans, and a limitations disclaimer.

VIII

AI-assisted analysis Optional

If configured, the AI assistant summarizes the graph. Only redacted summaries are transmitted — never raw requests or credentials.

Responsible Use
◆

Security and ethics

⚠

AttackGraph is for authorized security testing only. Only use it against systems you own or have explicit written permission to test. Unauthorized testing is illegal regardless of the tools used.

🔒

Local-first by design

All data stored at ~/.local/share/attackgraph/. No telemetry, no cloud sync, no external transmission except optional AI API calls.

⚖

Hypothesis-based findings

All findings are unvalidated hypotheses until manually confirmed. No finding is ever automatically marked as confirmed.

🤖

Safe AI integration

AI calls transmit only redacted graph summaries — never raw HTTP requests, credentials, session tokens, or full responses.

🚫

Scope enforcement

The crawler enforces your configured scope at every request. Robots.txt is respected by default.

Common questions

Everything you need to know before getting started.

AttackGraph is an open-source, local-first application security testing platform for Linux. It helps security researchers and penetration testers discover web application endpoints, model them as a directed graph, apply deterministic security analysis, and generate professional security reports — all without sending data to the cloud.

AttackGraph is designed for:

  • Penetration testers who need a structured workflow from discovery to report
  • Security researchers building an understanding of a web application's attack surface
  • Bug bounty hunters who want organized findings, attack paths, and reproducible steps
  • Security engineers assessing their own applications for weaknesses before a formal engagement

It requires Linux and assumes some familiarity with web application security concepts.

No. AttackGraph is local-first by design. All project data, crawl results, findings, graphs, and reports are stored on your machine at ~/.local/share/attackgraph/. There is no telemetry, no cloud sync, and no external communication — except optional AI API calls if you choose to configure an AI provider.

Even the AI assistant can run fully locally using Ollama with no API key required.

No. AttackGraph is a passive analysis and hypothesis generation platform, not an exploitation framework. It observes, models, and reasons about your application — it does not send attack payloads, attempt authentication bypasses, or execute any destructive actions.

All findings are clearly labelled as unvalidated hypotheses until you manually confirm them through your own authorized testing. AttackGraph never claims a vulnerability is confirmed from passive analysis alone.

AttackGraph currently supports Linux x86_64. It is available as:

  • AUR package (attackgraph-bin) for Arch Linux and Arch-based distributions
  • AppImage for any Linux x86_64 system — no installation required
  • .deb package for Debian, Ubuntu, and compatible distributions
  • Build from source on any Linux system with Python 3.11+, Node.js 18+, and Rust 1.75+

Windows and macOS are not currently supported.

Burp Suite and OWASP ZAP are HTTP proxies — they intercept, inspect, and replay traffic. AttackGraph is a graph analysis and reporting layer that sits above traffic collection.

In fact, AttackGraph can import your Burp Suite HTTP history to build its application graph. The two tools complement each other: use Burp to capture traffic, import it into AttackGraph to model the attack surface, generate test plans, and produce a structured report.

No. The AI assistant is entirely optional. Every core feature — crawling, traffic import, graph construction, security analysis, attack paths, test plans, and reports — works without any AI configuration.

If you want AI assistance, you can connect any OpenAI-compatible provider:

  • Ollama — runs locally, no API key, completely private
  • OpenAI — GPT-4o, GPT-4o-mini, o1
  • Google Gemini — Gemini 2.0 Flash, 1.5 Pro
  • OpenRouter — Claude, Llama, Mistral, and 200+ models

Yes, with reasonable configuration. The crawler is designed to be polite: it respects robots.txt by default, enforces your configured scope, and includes a rate limiter so you control the request rate.

That said, even passive crawling can trigger WAF alerts, consume server resources, or expose activity in logs. Always inform your team and have permission before running AttackGraph against any application — even one you own.
